# 大肥鱼 AI 大模型接入层设计 v1

> 补全 v1+ 设计中缺失的模型层。核心原则不变：**模型只负责"她怎么说"，永远不负责"她怎么做"**。
> 现状盘点 → 架构 → 安全护栏 → 分期落地。资产复用结论：旧桥接 `bridge/teammate_bridge.py` +
> `teammate_protocol.py` 是自有纯标准库代码（无 Knox/ZombieBuddy 依赖），测试覆盖完整，可直接改造。

## 0. 为什么 v1 没接模型（不是遗忘）

AGENTS.md 开发顺序铁律：身份/实体/行为/交互/存档核心闭环 → 全部实机验收 → 才接台词/语音/模型。
现在核心闭环代码已齐（生成已实机验收 ×3），模型层进入排期正当时。

## 1. 分层架构（游戏进程与模型进程严格隔离）

```
┌─ 游戏进程（Java agent + Lua）──────────────────────────┐
│ Lua: 事件触发（掉队/危险/重逢/闲聊限流/玩家看海…）        │
│   ↓ 组织上下文（天气/时间/距离/最近事件/羁绊阶段）         │
│ Java: DCStandaloneChat.request(ctx)                     │
│   ↓ 原子写请求文件（会话 nonce + 递增 seq）               │
│ 📮 mailbox/request-<npc>.wire  （进程边界：文件系统）      │
│ 📮 mailbox/reply-<npc>.wire                             │
│ Java: 每 tick 非阻塞轮询回信 → 校验 → 投递显示            │
└─────────────────────────────────────────────────────────┘
┌─ 桥接进程（复用改造 teammate_bridge.py，Python stdlib）──┐
│ 轮询请求 → 校验协议 → 组装 DeepSeek chat 请求             │
│   （system prompt = 大肥鱼人设卡 + 台词规范 + 上下文）      │
│ → 严格解析模型 JSON → 写回信文件                          │
└─────────────────────────────────────────────────────────┘
┌─ 语音进程（复用 tts.py）────────────────────────────────┐
│ 回信文本 → edge-tts（zh-CN 音色）→ 音频段注入游戏          │
└─────────────────────────────────────────────────────────┘
```

**游戏线程永不阻塞**：请求是写文件（微秒级），回信是 tick 里读文件（非阻塞）；桥接进程死了游戏照跑，只是她"今天不爱说话"。

## 2. 模型能做什么 / 不能做什么

**能做（输出只有 text 字段）**：
- 个性化台词：同一事件（掉队）按上下文/羁绊阶段生成不同说法，替代固定文案池轮换；
- 闲聊生成：40 分钟限流的闲聊从"预写 3 条"变成"基于当下场景生成"（雨夜+厨房+饿 → 她念叨罐头）；
- 对玩家行为的短评：玩家刚杀了一群丧尸回来，她说一句贴合的话。

**不能做（硬护栏）**：
- ❌ 输出动作/移动/战斗决策——协议里 `action` 字段只允许 `none`（v1.5 收窄：直接删掉 action 字段，模型纯文本）；
- ❌ 执行代码、改配置、访问文件系统——协议解析层拒绝一切额外键、控制字符、超长文本（512 字节截断不劈码点）；
- ❌ 知道玩家隐私/系统信息——上下文只含游戏内状态（天气、位置类型、事件名），绝不带路径/API key。

## 3. 安全护栏（继承自已测试的协议层，逐条有测试背书）

| 护栏 | 机制 | 来源 |
|---|---|---|
| fail-closed | 模型输出不合规则丢弃，静默降级到本地台词池 | test_teammate_bridge 既有用例 |
| 防重放 | 会话 nonce + 递增 seq，旧回信不被二次消费 | 同上 |
| 原子性 | 原子写（tempfile+replace），读者只见完整内容 | 同上 |
| 限流 | 桥接侧 min_interval（默认 8s）+ Lua 侧闲聊 40min 限流，双保险 | 同上 + 叙事设计 |
| 超时 | API 30s 超时；超时=本轮沉默，不重试不排队 | 同上 |
| 无凭据泄漏 | api_key 只存在于桥接进程 config，游戏进程不可见 | 既有配置面 |

## 4. 上下文包（喂给模型的全部信息）

```
system: 大肥鱼人设卡（憨稳馋/深海时间尺度/台词规范：一行内/简中/不报战术信息）
user:   {event: "掉队", weather: "小雨", time_of_day: "夜", bond_stage: 2,
         recent_events: ["玩家刚脱险"], distance_hint: "远"}
```
上下文由 Lua 从游戏状态抽取，全部是**枚举值或短标签**，无自由文本注入点（玩家不打字，天然无 prompt 注入面）。

## 6. 验收标准（实机）

- 拔掉桥接进程（kill），游戏帧率无波动、无错误弹窗，台词降级到本地池——**30 分钟无感**；
- 模型返回超长/带代码/带额外键的 JSON（注入测试样本），全部被拒且她当轮沉默；
- 同一事件（掉队）连续触发 5 次，模型版台词与本地池台词都出现，无重复刷屏；
- API key 出现在游戏进程内存/日志 → 0 次（grep 验收）。
