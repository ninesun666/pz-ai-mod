# AI 测试工装方案（现状 · 痛点 · 利器路线图）

> 原则：**能进程内做的绝不走 GUI**；GUI 只留最后一道"人眼抽样"。

## 0. 现状测试流程（我们实际在跑的）
1. 隔离启动：java 直启 + `-cachedir=<test-profile>`（等号！）+ zbNative agent + test-profile 四模组清单。
2. 引导自动化：`DC_AITeammateTest.lua` —— OnMainMenuEnter/OnTick → `MainScreen.continueLatestSave("Sandbox", <存档>)` 编程化载入 → RECOVER/TELEMETRY 遥测 → DC_MODEL_LIVE 邮箱观察。
3. 观察：Tee-Object 日志落盘 + grep；`shot.ps1` GDI 拷屏；`click_test_menu.ps1` user32 点击。
4. 判定：日志遥测行（机器）+ 截图（人读）。

## 1. AI 不友好环节清单（诚实版，按痛排序）
| # | 环节 | 为什么痛 |
|---|---|---|
| 1 | **UI 操作只能靠模拟鼠标** | 坐标随窗口/DPI 漂移；前台被用户抢占；双击/拖拽时序不稳；点错进错流程（创建页回退事故） |
| 2 | **画面语义不可靠** | OpenGL flip 时 GDI 拷屏出黑帧（与"未渲染"不可区分）；字形/UI 判定需要 vision 读图，慢且主观 |
| 3 | **游戏内部状态无外部接口** | 当前 UI 屏幕、暂停态、玩家/NPC 位置、模组加载状态——只能靠日志碎片拼 |
| 4 | **时间轴不可控** | 载入 30-60s、bink 视频阻塞（点击才过）、动画过渡——轮询等待全靠猜 |
| 5 | **强杀=脏存档** | 写入窗口内杀进程 → 后续载入回退/骷髅存档（实测两次事故） |
| 6 | **存档准备不可重复** | 验收需要特定状态（活玩家+已招募 NPC+指定坐标），手工准备无法复现 |
| 7 | **机器与用户共享** | 抢前台/鼠标会干扰用户；用户也可能动游戏窗口 |
| 8 | **中文 IME** | 真人输入法路径无法程序化复现（每家 IME 行为不同） |

## 2. 利器路线图（按优先级，每项含验收标准）

### P0-1 进程内测试驱动 `DCTestDriver.lua`（核心，一劳永逸）
- 落在测试模组内，仅测试 profile 启用。
- **命令信箱**：AI 写 JSON 到 `<test-profile>/driver/inbox/*.json` → 驱动每帧轮询执行 → 结果写 `outbox/*.json`。文件即协议，AI 天然会用。
- 快照命令 `snapshot`：每 tick 可得的全部真相一次性返回——当前 GameState/屏幕名、UIManager 活动窗口树（类名+坐标+文本）、玩家/NPC 坐标与目标、游戏速度、模组加载名单、最近日志行。
- **UI 操作原语（替代鼠标）**：`findUI(类名/文本)` → 返回元素引用；`clickUI(ref)` 直调 `onMouseDown/onMouseUp`；`setText(ref,"中文")` 直写文本框（绕过 IME）；`triggerAction(ref)` 直调按钮回调。
- 世界原语：`teleport(x,y)`、`spawnZombie(n)`、`setSpeed(0/1/2/3)`、`saveNow()`（正常存档退出基础）。
- **验收标准**：AI 全程不碰鼠标键盘完成"载入→右键队友→开对话→输入中文→提交→断言回复"全链路。

### P0-2 结构化遥测
- 关键路径改打单行 JSON（`[DCTEL] {...}`）：RECOVER、载入阶段、模型往返、错误。保留旧 print 兼容。
- **验收**：编排器用一行 grep+jq 断言任意验收点，不再靠人读日志。

### P0-3 会话编排器 `run-session.ps1`
- 职责：启动（等号 cachedir 模板）→ 等 `[DCTEL] ready` 标记（替代睡眠猜测）→ 执行 inbox 命令序列 → 收 outbox → **优雅退出**（驱动 Lua 调 `quit()` 正常存档，避免脏档）→ 落报告（pass/fail+快照 JSON+截图路径）。
- 健康检查：日志心跳超时 → 分级处置（先等待→再 dump 线程→最后才杀，杀前必须快照存档目录 mtime）。
- **验收**：一条命令完成一次全链路回归并产出机器可读报告。

### P1-1 存档工厂 `make-fixture.ps1` + 模板库
- 启动→驱动 Lua 造状态（传送/招募/等待 N tick）→ `saveNow()` 正常退出 → 存档复制为只读模板 → 每次测试**复制模板**开跑。
- **验收**：同一 fixture 连续 10 次载入结果一致。

### P1-2 游戏内截图通道
- 驱动 Lua 调 PZ 内置截图（写固定路径）或经 agent 做 GL readback；AI 拿到 PNG 后才用 vision——**不再依赖 GDI 拷屏**，黑帧问题消失。
- **验收**：任意时刻截图非黑且含 UI。

### P1-3 字形静态断言（回归用）
- fnt 是文本格式：bake 管线已断言 7,364 码位零缺字；补一条"UI 字符串全集 ⊆ fnt 字符集"的 CI 断言。屏幕像素级只留一次性人工抽样。
- （字体本体已由用户解决，本项仅作回归防线。）

### P2-1 IME 最小人工清单
- 只保留"系统级中文输入法在聊天框可输入"一条人测项；其余文本路径全走 P0-1 的 setText。

## 3. 实施顺序与依赖
P0-1 → P0-2 → P0-3（三件一体，先做驱动才有 ready 标记与优雅退出）；P1 任一独立。
预计工作量：P0 三件 ≈ 一个 Lua 文件 + 一个 ps1；P1-1 半天；P1-2 看 agent 侧能力。

## 4. 明确不做 / 降级
- 不做：全自动像素级 UI 回归（脆弱且 vision 成本高）——用 P0-1 的 UI 树快照替代像素比对。
- 降级：真人联机、跨机器分发——维持项目范围声明。
